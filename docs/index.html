claude-work-guard

Interrupts long, untracked Claude Code sessions to ask whether to file a JIRA ticket or cut a feature branch.

One nag per session, then quiet.

claude · ~/auth-refactor · main session active
$claude
> refactor the auth flow
elapsed ▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱ ▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰ 00:00 / 15:00
● Edit(src/auth/login.ts)
● Edit(src/auth/session.ts)
● Write(src/middleware/guard.ts)
● Edit(src/types.ts)
Hold on — we're 15 minutes into this session on main with 4 uncommitted files and no JIRA ticket referenced yet. Want me to:
  • file a JIRA ticket for this work
  • cut a feature branch before further edits
Or should we push through and sort it after?
>
kindhook lang bash + python depsnone
DESCRIPTION

Two hooks, one shell script, one small JSON file per session. No network, no daemon, no dependencies beyond bash and the system python3.

The clock starts on the first actual edit, not on session start — opening Claude for exploratory Q&A won't burn the threshold. The interrupt fires at most once per session; once you've answered (or declined), the hook stays quiet for the rest of it.

THE INTERRUPTION

The conversational pause shown above is Claude's user-facing translation of what the hook actually emits. The hook itself just prints this to stderr with exit 2; Claude Code forwards exit-2 stderr to the model as a blocking note, which is what causes Claude to pause and ask.

[ stderr · exit 2 ] 
⚠  Work-guard check (20 min into this session):
  •  4 uncommitted files
  •  no JIRA ticket referenced yet
  •  on default branch `main`

Pause and ask the user whether to:
  →  create or reference a JIRA ticket
  →  cut a feature branch before further edits
If they decline, continue and don't ask again.

Each bullet drops out individually when its condition isn't met. If both JIRA and branch conditions are already satisfied, the hook exits silently — no nag at all.

HOW IT WORKS

Wire two Claude Code hook points to the same shell script. The first watches user prompts; the second watches edits. Per-session state lives in a small JSON file under ~/.claude/work-guard/.

[ trigger · prompt mode ]
UserPromptSubmit
Every user message. Scans for a JIRA-style key (PROJ-123) and sets jira_seen.
[ trigger · edit mode ]
PostToolUse
Every Edit / Write / MultiEdit / NotebookEdit. Stamps first-edit time and checks the threshold.

On the first edit past the threshold, the script gathers facts — branch, dirty-file count, JIRA-seen flag — and decides whether to interrupt. See above for what the interrupt itself looks like.

TRIGGER CONDITIONS

The hook exits early — no state, no nag — when cwd isn't inside a git repo, or when the repo contains a .no-work-guard marker file at its root.

Otherwise the nag fires on the first edit that satisfies all of:

  1. Elapsed time since the first edit in this session ≥ threshold (default 15 minutes).
  2. No prior warning issued in this session.
  3. Either no JIRA-style key has been seen in any user prompt this session, or the repo's current branch is one of main, master, develop, trunk, dev.
INSTALLATION

Clone the repo, make the script executable, and add the two entries below to ~/.claude/settings.json. Use absolute paths — hooks don't get your shell's PATH expansion. Restart any active Claude Code sessions afterward so the new config loads.

»~/.claude/settings.json 
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "/Users/you/projects/claude-work-guard/claude-work-guard.sh prompt"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit|NotebookEdit",
        "hooks": [
          {
            "type": "command",
            "command": "/Users/you/projects/claude-work-guard/claude-work-guard.sh edit"
          }
        ]
      }
    ]
  }
}
CONFIGURATION
CLAUDE_WORK_GUARD_THRESHOLD
Env var, seconds. Default 900 (15 min). Example: export CLAUDE_WORK_GUARD_THRESHOLD=600 to nag after ten minutes instead.
.no-work-guard
Per-repo opt-out. Create an empty file at the repo root and the hook ignores that directory for good.
non-git directories
Always skipped automatically. Scratch dirs and one-off script folders won't trip it.
default-branch list
Edit the case "$branch" in main|master|develop|trunk|dev) ... line in the script.
state location
~/.claude/work-guard/<session_id>.json. Safe to delete at any time — recreated on the next edit.
